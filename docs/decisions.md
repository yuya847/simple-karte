# 設計の判断の記録

作りながら決めたことと、その理由。新しいものを上に足していく。

## 2026-11-02

### 救急外来は「病棟の医師から見た救急」に絞る
- 救急患者の一覧（来院・トリアージ・主訴・状態）、受付（架空の患者の登録）、入院（病名・体格・アレルギー・ベッド）までを作った。入院すると病棟マップと患者一覧に新入院として入り、すぐ入院時の指示を話せる。
- 作らないもの：保険証の確認・会計・算定・レセプトなどの医療事務。作品の主題（医師の指示の入力）から外れ、以前の自作（外来カルテ）とも区別しにくくなるため。
- トリアージ（JTAS）は看護師が判定して入れる値として持つ。アプリは緊急度を決めない。
- 4床室は男女別という病棟の約束をコードで判定し、性別の違う部屋は選べないようにした。

### 注射・処方カレンダーの「済み」は、時刻を過ぎたものとして出す
- この試作には、看護師の実施入力（投与した・服用した）がない。予定の時刻を過ぎたものを ✓ とし、画面にそう書いた。
- カレンダーから止めるときも、直接は止めず「中止の下書き」を右に入れる。確定は、ほかの下書きと同じく医師が押す。

### 経過表は、体温・脈拍・血圧を1つのグラフに重ねず、時間の軸をそろえた帯に分ける
- 紙の温度板は、1つのグラフに体温・脈拍・血圧を重ね、目盛りを3つ持つ。慣れた人には読みやすいが、目盛りの合わせ方しだいで、関係のない線どうしが連動して見える。
- 決めたこと：帯を縦に並べ、時間の軸だけをそろえる。色は温度板の約束（体温は青、脈拍は赤）に合わせ、血圧は上下の値を縦の線で結ぶ。色の組み合わせは、色覚の違いでも見分けられるかを検査の道具で確かめた（見出しと表での表示で補う）。
- グラフに触れると、その時刻の全部の値を1つの吹き出しに出す。同じ値は「表で見る」でも読める。

### 点滴量は、オーダから計算した概算として出す
- 実測の入る量（in）ではなく、有効な注射のオーダ（輸液の速度、溶解液の量×投与の回数）から、日ごとに計算する。今日中止したオーダは、今の時刻まで数える。画面に「オーダから計算」「概算」と書く。

### 病棟マップには、受け持ち以外の患者も架空で置く
- 受け持ちの4人だけでは、病棟の地図に見えない。ほかのチームの患者を架空で置き、灰色にして、カルテは開けないようにした。部屋番号は、多くの病院と同じく4と9を飛ばした。
- 受け持ちの患者には、値（最新の体温・SpO2）と出来事（今日の新しい結果、未確定の下書き、今日確定した件数）だけを出す。「要注意」のような判定はしない。

### 「20時間で」が1袋あたりか1日分かは、Claude ではなくコードが言葉から決める
- 何があったか：同じ指示「ヴィーンFは1日2本を続けて、20時間で」を2回試したところ、Claude は1回目に「どちらにも取れる」、2回目に「1日分」と返した。
- 決めたこと：1日に複数袋で点滴時間が言われたときは、時間の直前に「1本」「1本あたり」「2本を」「1日分を」などのはっきりした言葉があるかを、コードが見る。なければ Claude の答えにかかわらず「どちらにも取れる」として、両方の速度を計算した選択肢で医師に聞く（`scopeFromWords`）。
- 理由：あいまいさを解くのは医師の仕事。読み取りが毎回ぶれる部分は、決まった規則に移す。

### Claude に患者の情報を送らない
- Claude に送るのは、話した文と院内のマスターだけ。重複・日時・腎機能などの患者に関わる確認は、ブラウザの中のコードで行う。
- 理由：読み取りに患者の情報は要らない。送らなければ、漏れる心配も、AI が患者を見て判断する余地もない。

### Claude の答えは決まった形（スキーマ）にし、言われていない項目は空のまま返させる
- 言われていない量・経路・速度・日時を、Claude が「よくある値」で埋めると、医師が気づかないまま確定するおそれがある。空のまま返させ、抜けはコードが聞き返す。
- マスターにない番号を Claude が返したときは、コードが捨てて「マスターにない」として扱う。

### 聞き返しは、必ず選択肢で答えられるようにする（選択肢がないときは言い直し）
- 計算の結果（例：25mL/時と50mL/時）を選択肢のラベルに入れる。医師は計算をせずに選ぶだけ。
- 選択肢は、言われた言葉の別の読み方か、マスターにある候補だけ。量や薬を勧める選択肢は作らない。

### 速さ：Opus 5.5 の fast mode と effort low
- 最初の試験で、6件の指示の下書きに約15秒かかった。fast mode にすると約4〜5秒になった（2回目以降はマスター部分がキャッシュされる）。
- 1回あたりの料金はおよそ0.06ドル。fast mode が使えないときは普通の速さに切り替える。

### 「今日」はブラウザの時計（日本時間）で決め、架空の経過は「今日から何日前か」で持つ
- デモをいつ開いても、入院4日目の朝として読める。サーバーでは日付を描かない（日付をまたいだときの食い違いを避ける）。

### Claude に返させる形（スキーマ）に、空を表す null を使わない（2026-11-03）
- 何があったか：処置の項目（部位・大きさ・深さ・酸素の器具と流量）を足したところ、API が「出力の文法が大きすぎる」「null を許す項目は16個まで」と断った。それまでの形で null を許す項目が13個あり、上限に近かった。
- 決めたこと：Claude に渡す形（`AiWireResponse`）では、言われていないことを「""（文字）」「0（数）」「unspecified（選択）」で返させ、null を使わない。サーバーで受け取った直後に `fromWire()` でアプリの形（言われていないものは null）に戻す。画面とチェックのコードは変えない。
- 大きさは、Claude には言葉のまま（「12×10センチ」「150平方センチ」）写させ、数と面積はコードが読む（`parseSize`）。読めない言葉（「手のひら大」）は、範囲の区分を選択肢で聞く。

### 処置の算定は、点数表と通知の決まりをそのままコードにする（2026-11-03）
- 酸素は、指示の流量 × 動いていた分数を日ごとに足し、購入単価（架空の院の値。告示の単価以下）× 容積 × 補正率1.3（1円未満四捨五入）÷ 10（1点未満四捨五入）で点数にする。記録条件仕様の記録例（10L・2.31円 → 3点、300L・0.30円 → 12点）でテストした。実際の流量は看護記録で確かめる、と根拠に書く。
- 創傷処置・重度褥瘡処置の100cm²未満は、入院中は手術後14日までしか算定できない（J000 注1・J001-4 注2）。処置は出せるが手技料は算定せず、使った薬剤だけ算定する（第9部 通則 通知3）。処置の薬剤は15円以下を算定しない（J300 注1。投薬・注射の「1点」とは違う）。
- 重度褥瘡処置は D3〜D5 だけ、初回から2月を経過するまで1日につき。それ以降は創傷処置の例による（J001-4 注1）。2月の数え方は民法143条（応当日の前日、なければその月の末日）。
- 同じ日に創傷・褥瘡の処置が2つ以上あるときは、面積を合算するか（同じ疾病）、1つだけか（同じ部位）を人に確かめてもらう（通知 J000(2)(3)）。コードは決めない。
- 予定の処置は、時刻を過ぎたら実施したとみなす（注射と同じ。実施の記録はこの試作にない）。必要時の処置は、実施の記録（架空）があるものだけ数える。

### 部門の画面も「Claude は写すだけ、判定はコード、決めるのは人」で作る（2026-11-03）
- ユーザー：「搭載してない機能（透析、手術室、ワークシート印刷、患者一覧、救急受付、薬剤部系の仕事）」を作る。公開資料（厚労省の標準仕様の機能一覧、富士通の電子カルテを使う病院の調達仕様書の機能一覧、カタログ、薬剤師会の資料）で項目と流れを調べてから作った。病院が公開している画面写真入りの操作マニュアルは見つからなかった。
- Claude を使うのは、人の言葉を項目に写すところだけ：お薬手帳の薬の行（`/api/mochikomi`）、救急隊の電話（`/api/hotline`）、透析条件の変更（`/api/hd-order`）、手術申込（`/api/or-request`）。どれも null を許す項目を使わない形にした（上の「スキーマに null を使わない」と同じ理由）。
- コードがすること：同じ成分の重複、院内の薬との照合、除水量・除水速度と指示の上限、透析の時間の区分、手術室の重なりと締切、JTAS の再評価までの時間、麻酔の時間加算、各点数の決まり（告示・通知の原文で確かめた）。
- 人が決めること：トリアージの段階（看護師）、鑑別の確認（薬剤師）、持参薬をどうするか・条件の変更・手術の申込（医師）、「麻酔が困難な患者」（麻酔科医）。アプリは勧めない。
- 疑義照会で「変更する」と答えたら、前のオーダの中止の下書きを作り、前のオーダが中止されるまで照会を閉じない。照会で直したのに前の処方が残っていた、という事例が報告されているため。
- 救急外来医学管理料（令和8年度新設）と院内トリアージ実施体制加算は、基準にした病院の届出（管理料はなし、トリアージ加算はあり）から出す。トリアージ加算は管理料に加える加算なので、管理料の届出がないと算定できない、と出す。
- 人工腎臓は、基準の病院に「慢性維持透析１・２」の届出がないため「慢性維持透析３」。導入後1月は「その他の場合」（通知 J038(8)イ）。

### 処方は Rp で、チェックは「エラー」と「承知で確定できる警告」に分ける（2026-11-03）
- ユーザー：「処方も富士通を模倣して」。公開資料（静岡市薬剤師会が載せた富士通カルテの処方の留意事項）で読み取れた仕組みに合わせた：Rp ごとに薬を並べる、1日量を入れると1回量を並べて出す、用法（分N・服用時点）と日数、チェック結果は「エラー（確定できない）」と「承知コメントを付ければ確定できる警告」。画面の見た目は写さず、Simple Karte の色と部品で作った。
- 1回量は 1日量 ÷ 回数（コード）。割線のある錠剤だけ半錠を許す（マスターの印）。極量は添付文書の1日最大量を持つ薬だけ（アセトアミノフェン 4,000mg、ロキソプロフェン 180mg、アムロジピン 10mg）。
- アレルギーは、薬の分類（例：NSAIDs）がカルテのアレルギーの文に含まれるかをコードで見るだけ。交差反応の判断はしない。

### 画像検査の部位と生理検査の場所は、Claude ではなくコードが言葉から決める（2026-11-03）
- Claude は「胸部」「腹部骨盤」「ベッドサイドで」のような言葉を写すだけ。部位のマスターへの当てはめ（長い名前が勝つ）、場所・移動の言葉の読み取りはコード。
- 造影の確認：eGFR は日本人の推算式（194 × Cr^−1.094 × 年齢^−0.287、女性 × 0.739）で計算し、式を出す。30未満は「院内の取り決め（架空）」として放射線科と相談の承知を求める。決めるのは医師。
- 算定：同じ部位を同時に2枚以上撮ったら2〜5枚目は写真診断・撮影とも100分の50（第2節 通則3）。CT・MRI は同じ月の2回目以降は撮影料が100分の80（第3節 通則2。造影剤使用加算に掛けるかは「確かめる」を出す）。コンピューター断層診断は月1回なので、月の最初の1回だけ入れる。

### 検体検査は1項目ずつ。基準範囲は共用基準範囲を先に、判断値は分ける（2026-11-03）
- ユーザー：「血液検査の項目はSRLなどの項目を参考にして　WBC,CRP,Na,K,Mgなど」。SRL「総合検査案内 2026-2027（セントラルラボラトリー版）」の PDF で、項目の分け方・材料・容器・所要日数を調べた（Web 版の検索は開けなかった）。院内か外注かは架空の病院の設定。
- 基準範囲は JCCLS「共用基準範囲」（2022/10/01 版）を先に使い、そこにない項目（Mg、凝固、PCT、BNP など）は SRL の値。SRL の「基準値」には臨床判断値・カットオフが混ざる（NT-proBNP 125未満、TnT 0.100、PCT 0.50 など）ので、判断値として別に持つ。男女で違う項目は男女別。
- 1つの診療行為コードに複数の項目が入る（WBC・Hb・Plt → 末梢血液一般、Na・Cl → ナトリウム及びクロール）。1回の採血ではコードごとに1回だけ数える。
- 包括（項目数で点数が決まる）を生化学的検査（Ⅰ）のほかに、内分泌（D008 の12〜51、3項目以上 410／623／900点）、腫瘍マーカー（D009、2項目以上 230／290／385点）、出血・凝固（D006 の14〜34、3項目以上 530／722点）も告示どおり組んだ。どの項目がどの群かは医科診療行為マスターの列16。
- BNP・NT-proBNP を最初の検査の日から1週間以内に2つ行ったら、主たるもの（点数の高い方）だけ算定し、各実施日を摘要に書くよう「確かめる」を出す（D008 通知(7)イ・ウ）。電子点数表の「同じ週は背反3」は暦の週なので、通知の「1週間以内」をコードで数える。

### 説明・同意書は固定の雛形に患者の情報だけを入れる。数値は出典つきで分けて出す（2026-11-03）
- ユーザー：「同意書とかも作れる？造影CT、中心静脈カテーテル、包括的同意書とか」。病院が公開している同意書と、学会・ガイドラインを調べてから作った。他院の文章は写さず、架空の病院の文として書いた。
- 雛形の文は AI が作らず、書き換えもしない。差し込むのは患者の氏名・ID・病室・担当医・対象のオーダだけ。医師の追加の説明は医師が書く。
- 頻度の数値は、説明の文から分けて `facts`（出典つき）に置く。病院ごとの値（重い副作用で 2000人に1人〜2.5万人に1人）はばらつくため、学会の資料と論文の値を使った（日本医学放射線学会 2006、Katayama 1990、造影剤腎症ガイドライン2018、日本麻酔科学会ガイド2017、日本IVR学会ガイドライン2019、日本医療安全調査機構 提言第17号）。テストで「説明の文に % を書かない」「出典の一覧にない出典を使わない」を確かめる。
- 造影CTの問診は、日本医学放射線学会の推奨度 A・B の項目。中心静脈カテーテルは、日本医療安全調査機構の説明・同意書の例にあるリスク評価の項目を、医師が確かめる欄にした。
- 署名は紙でもらう前提（A4縦の印刷）。アプリは「説明して同意を得た／同意されなかった／撤回」と日時・説明者・同席者・代諾者を記録する。造影CTと中心静脈カテーテルのオーダーでは、同意書がなければ聞き返し、オーダーと一緒に下書きを作れる。
- 身体拘束は包括同意に含めず、別の書式にする（公開されている例がそうなっていたため）。

### オープンソースの電子カルテを調べて、足りない機能の上位から作った（2026-11-03）
- ユーザー：「ほかオープンソースのカルテなどあればその機能を調べて追加するか提案して」。OpenEMR・OpenMRS・Bahmni・GNU Health・VistA・Open eObs・OpenDolphin・ORCA などの公開文書だけを読み、コードは見ていない。
- 作ったもの：バイタルの入力と NEWS2、監査ログ、事前指示（DNAR）と注意の掲示、与薬・実施の記録（照合）、口頭指示と医師の承認。
- NEWS2 は英国 Royal College of Physicians（2017）の点数表をコードで計算する。SpO2 は Scale 1 だけ（Scale 2 を使うかは医師が決める）。対応は病棟の取り決めと医師の判断で、アプリは観察の目安を参考として出すだけ。
- 監査ログは「AI が写した」と「人が確定した」を分け、追記だけで残す。試作ではブラウザのメモリにだけあり、本番の仕組みでは書き換えられない保管先に送る想定。
- 事前指示は、DNAR を「心停止時に心肺蘇生をしない指示で、ほかの治療を控えることではない」と画面に出す（日本集中治療医学会 2017 年の勧告）。ほかの治療は項目ごとに医師が記録する。AI は勧めない。
- 与薬の照合は、リストバンドと薬・検体のラベルをコードで照らし合わせる（患者・薬・時刻）。別の患者なら記録できない。前後60分（架空の病棟の取り決め）を外れたら承知が要る。この画面を開く前の分は、前の勤務帯が記録したものとして扱う。算定はこれまでどおり予定の時刻で数える（実施の記録とつなぐのは今後）。
- 口頭指示は、看護師が代わりに入力し、医師が24時間以内（架空の病院の取り決め）に承認する。期限はコードが数える。

### 食事・TDM・退院時サマリーも「Claude は写す・分けるだけ、計算と確認はコード」（2026-11-03）
- ユーザー：「2全部」（薬剤師の業務の続き（TDM など）、退院サマリ・診療情報提供書、食事オーダー、看護必要度）。点数と決まりは令和8年度の告示・通知と、手元の医科診療行為マスター（2026-11-02 版）で確かめてから入れる。
- 食事：Claude は「明日の昼から嚥下食コード1j」を項目に写すだけ。どの食事から変わるか、栄養科の締切（架空：朝食は前日17時、昼食は当日10時、夕食は当日15時）、検査の前の食止め（架空の約束：腹部エコー・造影CT の前の1食）、絶食中の内服の確認はコード。嚥下調整食は日本摂食嚥下リハビリテーション学会の分類2021のコードで持つ。
- TDM：バンコマイシンの2点採血（同じ投与間隔のピークとトラフ、定常状態）から、1-コンパートメント・間欠点滴の式（Sawchuk-Zaske 法）で k・Vd・CL・AUC24 を出し、式をすべて画面に出す。トラフ1点では AUC を出さない（集団の値を使うベイズ推定が要るため）。ほかの投与の予測は、同じ k と CL で計算するだけ。投与量の提案は薬剤師が自分の言葉で書き、医師が確認する。アプリは勧めない。自作の抗菌薬の計算ツールは開かず、教科書の式から新しく書いた。
- 退院時サマリー：病名・アレルギー・感染症・注射と期間・処置・培養・画像・検査の推移・退院時処方はカルテからコードで集める（AI に事実を書かせない）。医師の口述は、Claude が文を5つの欄に分けるだけ（足さない・言い換えない・決められない文は「欄が決められなかった文」に返す）。退院前に、有効なままの注射・結果待ちの培養・口頭指示の承認待ち・説明前の同意書を出す。紹介状（診療情報提供書）は同じ事実から作る。

### TDM の目標と特定薬剤治療管理料１（2026-11-03）
