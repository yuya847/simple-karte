# IC を声で記録（インフォームドコンセントの会話から IC の記録を作る）

説明・同意書（右の道具「同意書」）と、記事のテンプレート「ICの記録」「IC（簡易）」から開くウインドウです。
患者さんと医師（と家族・看護師）の会話を文字にし、話し手と時刻のついた書き起こしから IC の記録を作ります。
決めるのは医師で、AI は入力係です。Claude は話し手の札を見立てることと、発言の文をそのまま欄に置くことだけをします。

## 流れ

1. **同意の印**：患者さん（または代理の方と続柄）が「録音と、クラウドの音声認識・文字起こし」に同意したことを記録します。
   誰がいつ記録したかが残り、印がないと録れません。同意は記事（`録音とクラウドの音声認識・文字起こしへの同意：…`）と監査ログに残ります。
2. **録る**：ブラウザの音声認識（Web Speech API）で文字にします。画面の「いま話している人」（医師・患者・家族・看護師、キーの 1〜4）を
   押すと、その人の発言として行が付きます。行の時刻と話し手は、その発言が始まったときのものです。
3. **話し手を整える**：札のない行について、Claude が話し手（医師・患者・家族・不明）を見立てます。人が付けた札は変えません。
   見立ては「見立て」の印で出し、医師が選び直せます。
4. **IC の記録にする**：Claude が発言を「説明内容（医師）・相手の反応（患者・家族）・同席者」の欄に置きます。
   説明医師と説明を受けた人は、ログインした医師・同意の印・話し手からコードで入れます。
5. **確定**：医師が全部の欄を確かめて直し、「記事として確定」すると記事になります。記事には書き起こしの全文（話し手・時刻つき）が付きます。

## 送るもの・送らないもの

| もの | 行き先 |
| --- | --- |
| 声 | ブラウザの音声認識（Chrome では Google のサービス、Safari では Apple の音声認識）。このアプリのサーバーには送らず、保存もしない |
| 書き起こしの文（置き換え前） | この端末の画面と、確定した記事だけ |
| 置き換えた文（行番号・話し手つき） | `/api/ic-transcript` → Claude（Anthropic）。送る前に画面で見せる |

同意の文には、声がブラウザの音声認識のサービスに送られること、置き換えた文が Claude に送られることを書いています。

## 匿名化（置き換え）

送る前に、コードで次を `［氏名］` `［患者番号］` `［電話］` `［日付］` `［住所］` `［部屋］` に置き換えます（`src/lib/ic/anonymize.ts`）。

- MCP と同じ置き換え（`src/lib/mcp/redact.ts` の `redact`）：架空の患者・家族・連絡先・記事を書いた職員の名前、電話・日付・住所・部屋番号らしい表記
- その患者の名前と読み（カタカナ・ひらがな）、家族と連絡先、病院の職員（医師・看護師ほか）の名前
- 1文字の名前と2文字のひらがなの読みは「さん・様・ちゃん・くん」の前だけ（「とめます」の「とめ」を消さない）

サーバー（`src/app/api/ic-transcript/route.ts`）でも、受け取った文にもう一度 `redact` をかけます。
API は患者の名前・ID・カルテの情報を受け取りません（行番号・話し手・置き換えた文だけ）。

Claude が返すのは「行番号と、その行から写した部分（`""` は行全体）」だけです。
コードは、返った部分がその行（送った文）の中にあるかを確かめ（空白の違いは無視）、ないもの＝Claude が足したり変えたりした文は欄に入れず、件数を出します（`src/lib/ic/verify.ts`）。
確かめた部分は、置き換える前の元の言葉に戻して欄に入れます（`［氏名］` に触れる部分は名前ごと戻す）。

## 声で話し手を分けるサービス（話者分離）につなぐ

いまの形は鍵なしで動きます（ブラウザの音声認識＋人が押す話し手＋Claude の見立て）。
声そのもので話し手を分けたいときは、話者分離（speaker diarization）のある音声認識のクラウドサービスにつなぎます。
つなぐ口は `src/lib/ic/diarize.ts` に形だけあります（`adapterFor` はまだどのサービスにも `null` を返します）。

### 鍵の置き方

鍵はサーバーの環境変数に置き、リポジトリには入れません（`.env.local` は git に入りません。Vercel では Project Settings → Environment Variables）。

```
IC_DIARIZE_PROVIDER=amivoice   # amivoice | google | aws | azure
IC_DIARIZE_KEY=...             # そのサービスの鍵
IC_DIARIZE_REGION=...          # 要るサービスだけ（例：asia-northeast1, ap-northeast-1, japaneast）
```

`diarizeConfig()` は2つ（PROVIDER と KEY）がそろわないと `null` を返し、そのときは使いません。

### つなぎ方（形）

- 声はブラウザから**直接**そのサービスへ送ります。サーバーは鍵から短い時間だけ使えるトークンを作って渡すだけにし（`issueToken`）、声を受け取らず保存もしません。
- サービスの結果（`speaker0`・`speaker1` のような札と、時刻と文）を `DiarizedSegment` に読み（`readResult`）、`segmentsToLines` で画面の行にします。
- サービスの札は人ではないので、どの札が医師・患者・家族かは医師が選びます（`mapTags`）。選ばなかった札の行は札なしのままで、Claude の見立てと医師の確認は今と同じです。
- 同意の文に、声を送るサービスの名前を足します。

### 候補（使う前に、日本語の話者分離に対応しているかと契約の条件を必ず確かめる）

| サービス | 話者分離 | 確かめること |
| --- | --- | --- |
| AmiVoice API（アドバンスト・メディア） | 非同期 HTTP API で `speakerDiarization=True`。結果は `speaker0` のような札。<https://docs.amivoice.com/en/amivoice-api/manual/speaker-diarization> | 医療向けのエンジンで使えるか、リアルタイム（WebSocket）で使えるか |
| Google Cloud Speech-to-Text V2 | 言語の表では ja-JP の chirp_3（asia-northeast1）に話者分離がある。<https://cloud.google.com/speech-to-text/v2/docs/speech-to-text-supported-languages> | chirp_3 のページの話者分離の言語に日本語がない（食い違い）。ストリーミングでは使えない |
| Amazon Transcribe | 話者分離（バッチ・ストリーミング）。<https://docs.aws.amazon.com/transcribe/latest/dg/diarization.html> | ja-JP で使えるか |
| Azure AI Speech | 会話の文字起こしで話者分離 | ja-JP・国内リージョンで使えるか |

（2026-11-07 に各社の公開文書で調べた。対応は変わるので、つなぐときにもう一度確かめる。）

### 実際の病院で使う前に

- 医療情報を扱うクラウドサービスの安全管理（厚生労働省「医療情報システムの安全管理に関するガイドライン」と、総務省・経済産業省の事業者向けガイドライン）に沿って、契約・保存場所（国内か）・保存期間・学習に使われないかを確かめる。
- 病院としての同意の文（説明書）を決める。この画面の同意の文は試作のものです。
- この試作のデータはすべて架空です。
