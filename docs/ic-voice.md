# IC を声で記録（インフォームドコンセントの会話から IC の記録を作る）

説明・同意書（右の道具「同意書」）と、記事のテンプレート「ICの記録」「IC（簡易）」から開くウインドウです。
患者さんと医師（と家族・看護師）の会話を文字にし、話し手と時刻のついた書き起こしから IC の記録を作ります。
決めるのは医師で、AI は入力係です。Claude は話し手の札を見立てることと、発言の文をそのまま欄に置くことだけをします。

## 流れ

1. **同意の印**：患者さん（または代理の方と続柄）が「録音と、クラウドの音声認識・文字起こし」に同意したことを記録します。
   誰がいつ記録したかが残り、印がないと録れず、何も送りません。同意は記事（`録音とクラウドの音声認識・文字起こしへの同意：…`）と監査ログに残ります。
2. **録る**：ブラウザの音声認識（Web Speech API）で文字にします。行の時刻と話し手は、その発言が始まったときのものです。
   話している人（医師・患者・家族・看護師、キーの 1〜4）を押すと、その人の発言として札が付きます（押さなくてもよい）。
3. **話し手が自動で付く（文脈で）**：札のない行は、録っている間も（6行たまるか、いちばん古い行が20秒待ったら）、止めたときにも、
   名前などを置き換えた文が Claude に送られ、話し手（医師・患者・家族・不明）の見立てが「見立て」の印で付きます。押す釦はありません。
   人が付けた札は変えず、医師はいつでも選び直せます。「話し手を整える」は、札のない行を全部もう一度見立てさせます。
4. **声でも分ける（押したときだけ）**：声そのもので話し手を分けます。声はこの端末の外に出しません（下の「声での分離」）。
   止めたあと、声の番号（同じ声＝同じ番号）を行に時刻で合わせ、どの番号が医師・患者・家族かを Claude が置き換えた文から当てます（番号ごとに1人）。
   声で付いた見立ては文脈の見立てより優先し、人の札はどちらより優先します。足の欄の「うち見立て n（声 m）」で、どちらで分けたかが分かります。
5. **IC の記録にする**：Claude が発言を「説明内容（医師）・相手の反応（患者・家族）・同席者」の欄に置きます。
   説明医師と説明を受けた人は、ログインした医師・同意の印・話し手からコードで入れます。
6. **確定**：医師が全部の欄を確かめて直し、「記事として確定」すると記事になります。記事には書き起こしの全文（話し手・時刻つき）と、
   Claude がしたこと（声で分けたときは「声の区切りは端末の中で sherpa-onnx」）が付きます。

### 送った文を見る・送る前に見る

- 上の「送った文を見る（n回）」で、Claude に送った文（行番号・話し手・置き換えた文）を、いつでも全部見られます。
- 「送る前に見る」に印を付けると（この端末のみに適用されます）、自動では送らず、前と同じく「話し手を整える」「IC の記録にする」を
  押したときに送る文を見せ、「この文を Claude に送る」で送ります。

### 自動で送る量と回数の上限（料金と速さのため。`src/lib/ic/auto.ts`）

| 上限 | 値 |
| --- | --- |
| 送るきっかけ | 待っている行が6行、またはいちばん古い行が20秒待った。止めたとき・文を貼ったときはすぐ |
| 間隔 | 8秒より詰めない。失敗したら 30秒×続いた回数 待つ。3回続けて失敗したら自動はやめる（釦は使える） |
| 1回に送る量 | 60行・6,000文字まで（前の12行を文脈として含む）。1行は1,000文字まで |
| 1つのウインドウで | 60回まで（あとは「話し手を整える」で） |
| サーバー（1つの IP で10分に） | 自動の見立て 45回、声の番号 20回（`/api/ic-transcript`。記録の欄は他の API と同じ 20回） |

監査ログには、録っている間の自動の見立てをまとめて1件（止めたとき）、止めたあとは1回ごとに1件残します。

## 送るもの・送らないもの

| もの | 行き先 |
| --- | --- |
| 声（文字にするため） | ブラウザの音声認識（Chrome では Google のサービス、Safari では Apple の音声認識）。このアプリのサーバーには送らず、保存もしない |
| 声（声でも分けるとき） | この端末のブラウザの中だけ（Web Worker の sherpa-onnx）。数分ごとの区切りを分け終えたら捨てる。どこにも送らず、保存もしない |
| 書き起こしの文（置き換え前） | この端末の画面と、確定した記事だけ |
| 置き換えた文（行番号・話し手、声の番号つき） | `/api/ic-transcript` → Claude（Anthropic）。「送った文を見る」でいつでも見られる |

同意の文には、声がブラウザの音声認識のサービスに送られること、置き換えた文が Claude に送られることを書いています。
声で分けるときも声は端末の外に出ないので、同意の文は変えていません。

## 匿名化（置き換え）

送る前に、コードで次を `［氏名］` `［患者番号］` `［電話］` `［日付］` `［住所］` `［部屋］` に置き換えます（`src/lib/ic/anonymize.ts`）。

- MCP と同じ置き換え（`src/lib/mcp/redact.ts` の `redact`）：架空の患者・家族・連絡先・記事を書いた職員の名前、電話・日付・住所・部屋番号らしい表記
- その患者の名前と読み（カタカナ・ひらがな）、家族と連絡先、病院の職員（医師・看護師ほか）の名前
- 1文字の名前と2文字のひらがなの読みは「さん・様・ちゃん・くん」の前だけ（「とめます」の「とめ」を消さない）

サーバー（`src/app/api/ic-transcript/route.ts`）でも、受け取った文にもう一度 `redact` をかけます。
API は患者の名前・ID・カルテの情報と声を受け取りません（行番号・話し手・置き換えた文と、声で分けたときは声の番号だけ）。

Claude が返すのは「行番号と、その行から写した部分（`""` は行全体）」だけです。
コードは、返った部分がその行（送った文）の中にあるかを確かめ（空白の違いは無視）、ないもの＝Claude が足したり変えたりした文は欄に入れず、件数を出します（`src/lib/ic/verify.ts`）。
確かめた部分は、置き換える前の元の言葉に戻して欄に入れます（`［氏名］` に触れる部分は名前ごと戻す）。

## 声での分離（端末の中で。オープンソース）

### 選んだもの：sherpa-onnx の話者分離を WebAssembly でブラウザの中で動かす

- **声が端末の外に出ない**：クラウドに声を送らないので、声（匿名にできない）の送り先を同意に足さずに済みます。鍵も要りません。
- **ライセンス**：sherpa-onnx は Apache-2.0。中のモデルは pyannote segmentation 3.0（MIT）と 3D-Speaker の ERes2Net（Apache-2.0）。
  出どころ・ハッシュ・ライセンスの文面は `public/diarize/NOTICE.txt` と同じ場所の LICENSE-*.txt。
- **大きさ**：公開リリースの WebAssembly 版（v1.13.7）をそのまま `public/diarize/` に置いています。`.data`（モデル）45.6 MB・`.wasm` 12.4 MB・
  `.js` 0.1 MB、合わせて約 58 MB。「声でも分ける」を押したときだけ読み込み、あとはブラウザのキャッシュから読みます。
- **日本語**：話者の特徴（声の質）で分けるので、言葉の種類にはよらない作りです。ただし日本語の会話での精度はまだ確かめていません
  （確かめた見本は sherpa-onnx の中国語4人・英語2人の録音。中国語4人の57秒は、Mac のヘッドレスの Chromium で約8秒で分けられた）。
- **速さの工夫**：分析の窓（10秒）をずらす幅を 1/4 にしています（見本の 0.1 より約2倍速く、見本では同じ区切り）。録音は5分ごとに区切って、
  録りながら順に分けるので、止めてから待つのは最後の区切りの分だけです。

### 仕組み（`src/lib/ic/use-voice-diarizer.ts`・`src/lib/ic/diarize.ts`・`public/diarize/ic-diarize-worker.js`）

1. 「声でも分ける」を押すと Web Worker を作り、モデルを読み込みます（読み込みの割合を札に出す）。
2. 録っている間、ブラウザの音声認識と並べて MediaRecorder で声を録ります（Opus）。5分ごとと止めたときに、その区切りを 16 kHz に直して Worker に渡します。
3. Worker は sherpa-onnx で、区切りの中の「時刻と話者の番号（0, 1, …）」を返します。番号は区切りごとに独立です（`2-s0` = 2番目の区切りの話者0）。
4. 止めて全部の区切りを分け終えたら、行の時刻（話し始めの 1.5 秒前〜話し終わり）といちばん長く重なる番号を、その行の声の番号にします（`voicesForLines`）。
5. 声の番号つきの置き換えた文を Claude に送り（`mode: "voices"`）、番号ごとに医師・患者・家族・不明を返させます。人が付けた札は事実として使わせます。
   「不明」の番号は見立てを変えません。

| 形 | もの | ライセンス・条件 | 向き・不向き |
| --- | --- | --- | --- |
| 院内のサーバーで OSS | pyannote.audio（<https://github.com/pyannote/pyannote-audio>） | MIT。学習済みの `pyannote/speaker-diarization-3.1` は MIT だが Hugging Face で利用条件への同意（トークン）が要る。`community-1` は CC-BY-4.0 | Python と GPU のサーバーが要る。声は院内から出ない |
| 院内のサーバーで OSS | WhisperX（<https://github.com/m-bain/whisperX>） | BSD-2-Clause。話者分離は pyannote を使う | 文字起こしと話者分離を一度に。同上 |
| 院内のサーバーで OSS | NVIDIA NeMo（<https://github.com/NVIDIA/NeMo>） | Apache-2.0 | GPU 前提。大きい |
| クラウド | AmiVoice API（<https://docs.amivoice.com/amivoice-api/manual/speaker-diarization>） | 同期 HTTP で `segmenterProperties=useDiarizer=1`、結果の単語ごとに `speaker0` などの札。医療の会話のエンジン `-a-medical`。ログ保存なしの入口 `https://acp-api.amivoice.com/v1/nolog/recognize`。1回 16,777,215 バイトまで（<https://docs.amivoice.com/amivoice-api/manual/limitations>）。会話_医療・ログ保存なし 222.75円/時間（税込）、各エンジン月60分無料（<https://acp.amivoice.com/amivoice_api/price/>） | 日本語の医療の語彙。声そのものを送るので同意の文に送り先を足す。鍵（API キー）はマイページの「接続情報」で発行 |
| クラウド | Amazon Transcribe（<https://docs.aws.amazon.com/transcribe/latest/dg/supported-languages.html>） | ja-JP はバッチ（S3 が要る）とストリーミング | 設定が多い（IAM・S3） |
| クラウド | Google Cloud Speech-to-Text（Chirp 3。<https://docs.cloud.google.com/speech-to-text/docs/models/chirp-3>） | ja-JP の話者分離は BatchRecognize（と Recognize）。リージョンは us・eu | 国内のリージョンで使えない |
| クラウド | Azure AI Speech（fast transcription。<https://learn.microsoft.com/en-us/azure/ai-services/speech-service/fast-transcription-create>） | `diarization` を有効に。ja-JP を含む。5時間・500 MB 未満 | リソース名と鍵が要る |

院内のサーバーやクラウドにつなぐときは、Worker の代わりに「区切り（時刻と話者の番号）」を返す口を作れば、`fromSherpa` の代わりの読み取りだけで、
行に合わせる所（`voicesForLines`）から先はそのまま使えます。クラウドに声を送るときは、同意の文に送り先を足し、鍵はサーバーの環境変数に置いて
リポジトリに入れません（Vercel では Project Settings → Environment Variables。入れるのはユーザー本人）。

## 実際の病院で使う前に

- 声での分離が、日本語の説明の会話（2〜4人、診察室や病室の音）でどれだけ分けられるかを、架空の録音で確かめる（分ける幅の閾値は `public/diarize/ic-diarize-worker.js` の `threshold`）。
- 医療情報を扱うクラウドサービスの安全管理（厚生労働省「医療情報システムの安全管理に関するガイドライン」と、総務省・経済産業省の事業者向けガイドライン）に沿って、契約・保存場所（国内か）・保存期間・学習に使われないかを確かめる。
- 病院としての同意の文（説明書）を決める。この画面の同意の文は試作のものです。
- この試作のデータはすべて架空です。
